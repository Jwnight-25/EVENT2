# 股票选择、删除与恢复

更新时间：2026-10-26。

股票选择框旁保留“＋”添加按钮，并增加垃圾桶“删除当前股票”按钮。删除指从关注列表移出，确认框明确显示股票名称及代码、数据保留和后台行为；不是永久删除数据库文件或历史记录。取消不产生变化。

## 使用行为

- 确认移出后从选择列表隐藏，自动切换到剩余第一只股票；最后一只移出后显示空列表和添加入口。
- 行情、导入、快照、模型、预测、误差、积分、情报与对话等仍关联原stock_id，数据不删除。
- “添加股票”窗口显示已移出的股票，可点“恢复关注”；也可输入原交易所/代码重新添加。两种方式均恢复原stock_id及原名称，不生成重复历史。
- 活跃列表已有的同交易所/代码仍返回重复提示。相同代码但不同交易所沿用已有唯一约束。
- 股票移出后不新增行情更新、自动训练/预测批次及情报刷新。仅等待数据且未创建任务的批次标为paused；已提交的任务继续完成，历史收盘核对继续按原规则处理，不取消用户正在运行的任务。
- 在原目标日09:15之前恢复时，paused批次可重新等待数据、继续准备；截止后不补造历史预测。

## 历史与后台

stocks增加is_active，既有股票默认true。新增stock_watch_events，按stock_id记录每次实际移出/恢复的状态与changed_at，重复请求不新增事件。恢复后的漏跑检查参考每个交易日09:15时的关注状态，主动移出期间不记为缺少自动批次；已存在的模型与积分不改写。

固定行情来源和MarketFeed.enabled的原设置不被删除/恢复覆盖。自动调度只选择活跃股票；查询已移出股票的更新状态时enabled=false、next_check_at为空。历史读取仍可通过原ID进行；这是一款个人本机工具，不将移出关注当作访问权限控制。

## 接口

| 接口 | 行为 |
|---|---|
| GET /stocks | 默认仅返回活跃股票 |
| GET /stocks?include_inactive=true | 同时返回已移出股票，含is_active |
| DELETE /stocks/{id} | 幂等移出，返回changed、is_active、data_preserved |
| POST /stocks/{id}/restore | 幂等恢复，返回原股票 |
| POST /stocks | 新增为201；已移出同代码恢复为200；活跃重复为409 |

写入使用现有存储锁与SQLite提前写锁/PostgreSQL行锁，DELETE与POST同样受本机来源限制和完整备份互斥保护。新迁移e12a562e8c39不删除既有业务表或记录，完整备份包含关注状态和变更事件。
